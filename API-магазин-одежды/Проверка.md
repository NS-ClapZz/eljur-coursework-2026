# Моя проверка API магазина одежды

- Я выполнил `dotnet build ClothesApi.csproj --no-restore`: сборка прошла успешно, 0 ошибок и предупреждений. SDK показал только информационное уведомление о предварительной версии.

## Локальные проверки API

- Я проверил `GET /api/health` — получил 200.
- Я проверил `GET /api/clothing?search=Футболка` — получил 200, поиск вернул товар.
- Я проверил `GET /api/orders` без входа — получил 401.
- Я проверил регистрацию и вход покупателя — получил 201 и 200.
- Я проверил создание заказа и чтение истории покупателя — получил 201 и 200.
- Я проверил вход менеджера и список заказов по статусу — получил 200.
- Я проверил изменение статуса заказа, остатка размера и доступности товара — получил 200.
- Я проверил вызов менеджерского endpoint обычным покупателем — получил 403.

## Проверка в Postman

- Я отправил из Postman Lightweight API Client `GET http://localhost:5000/api/health` — получил `200 OK` и JSON `{"status":"ok"}`. Снимок: `docs/screenshots/postman-get-health-200.jpeg`.
- Я отправил `GET http://localhost:5000/api/clothing` — получил `200 OK` и 2 товара. Снимок: `docs/screenshots/postman-get-clothing-200.jpeg`.
- Полную коллекцию Postman я ещё не запускал: для доступа к коллекциям и окружениям приложение требует вход в аккаунт. Остальные локальные HTTP-сценарии проверены отдельно.

Я использовал временные учётные данные и тестовую базу вне исходников и ZIP-архива.
