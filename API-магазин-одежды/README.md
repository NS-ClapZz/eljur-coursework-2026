# ИСРПО 12–13: API магазина одежды

Я подготовил ASP.NET Core API с SQLite. Я реализовал каталог и поиск без учёта регистра, регистрацию и вход, хеширование паролей, роль менеджера, учёт наличия размеров, создание заказов с проверкой и списанием остатков, историю заказов с фильтром по статусу, управление остатками, доступностью товара и статусами заказов. Для каждого заказа я сохраняю название, размер и цену на момент покупки.

Я предусмотрел настройку менеджера через `CLOTHES_MANAGER_PASSWORD`; логин задаётся через `CLOTHES_MANAGER_LOGIN` и по умолчанию равен `manager`. При первом запуске каталог и база создаются автоматически. Я собрал проект: 0 ошибок и 0 предупреждений. Затем прогнал коллекцию из 13 запросов в Newman на отдельной временной SQLite-базе: все 22 автоматические проверки прошли. В том числе проверены поиск по строчным буквам, регистрация и вход покупателя, заказ, вход менеджера, смена статуса, остатка и доступности товара.

Я добавил коллекцию `ClothesApi.postman_collection.json` и окружение `ClothesApi.postman_environment.json`. Для локального прогона я указываю адрес API и задаю `managerPassword` только в текущем значении окружения Postman; оно совпадает с `CLOTHES_MANAGER_PASSWORD` запущенного API. Пароль не сохраняю в экспортируемом окружении или репозитории. Коллекция сама создаёт уникальный логин покупателя на каждый прогон. Для поиска в Postman Lightweight API Client я также проверил `GET /api/health` и `GET /api/clothing`; оба вернули `200 OK`, снимки лежат в `docs/screenshots/`.

Я вошёл в Postman Desktop и запустил сохранённую в рабочем пространстве коллекцию: все 13 запросов завершились HTTP-ответами 200/201. В этой копии нет Postman-тестов (Runner показывает «No tests found»); в сдаваемой коллекции я добавил 22 assertions и проверил их Newman. В исходном условии есть командные пункты: совместная работа в GitHub, распределение задач, ветки, постепенные коммиты и демонстрация запросов в Postman. Я выполняю проект самостоятельно и не заявляю вклад команды или преподавателя.
